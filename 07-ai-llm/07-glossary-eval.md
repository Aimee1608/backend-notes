# 能力评测词扫盲：跑分怎么看，为什么跑分高体感差

新模型发布必配一张跑分表：MMLU 92.3、SWE-bench 78.5、GPQA 85.1，全线超越竞品。

然后你实际用起来，感觉还不如手里的旧模型。跑分和体感的落差从哪来？这篇把评测相关的词理清楚，顺便回答这个问题。

---

## Zero-shot / Few-shot：考试时给不给例题

这两个词最初就来自评测场景，描述的是**给模型出题的方式**：

- **Zero-shot（零样本）**：直接出题，不给示例。"判断这句话的情感倾向：……"
- **Few-shot（少样本）**：先给几道带答案的例题，再出正式题。相当于开卷前先看三道真题

早年模型能力弱，Few-shot 和 Zero-shot 的成绩差距很大，所以跑分表会标注"5-shot"（给 5 个例子测出来的）。现在的强模型两者差距缩小，越来越多的评测直接用 Zero-shot——这本身就是模型能力提升的一个标志。

## In-context Learning：不改参数的"学习"

Few-shot 为什么有效？背后的机制叫 **In-context Learning（上下文学习，ICL）**：模型从上下文里的示例中"临时学会"任务模式，全程不更新任何参数。

这是大模型最神奇的性质之一——传统机器学习里"学习"意味着训练调参，而 LLM 只靠"看几个例子"就能现场适应新任务。请求结束，这个"学习"也随之消失，下次要重新给例子。

## 涌现能力（Emergent Abilities）

指模型规模跨过某个阈值后**突然出现**的能力——小模型完全做不了，大模型忽然就会了，中间没有平滑过渡。多步推理、代码生成都曾被归为涌现能力。

这个词要辩证看：有研究认为部分"涌现"是评测指标不连续造成的错觉（能力其实在平滑增长，只是评分方式让它看起来像突变）。看到宣传里的"涌现"，理解成"规模到了能力才解锁"就好，不必过度神化。

---

## Benchmark：标准化考卷

Benchmark 就是一套固定的测试题集 + 评分标准。常见的几类：

- **知识与推理**：MMLU（多学科选择题）、GPQA（研究生级别的科学题，难度高、更能拉开差距）
- **代码**：HumanEval（写函数通过测试用例，早年主流、现已接近饱和）、**SWE-bench**（从真实 GitHub issue 出发修代码库的 bug，目前代码能力的黄金标准——它测的不是"会不会写函数"，是"能不能在真实工程里干活"）
- **数学**：GSM8K（小学应用题，已饱和）、AIME（竞赛级）
- **Agent 能力**：各类模拟真实任务的评测（订机票、操作网页、多步工具调用），近两年增长最快的评测类别

读跑分表的两个要点：

**一看饱和度**。一个 Benchmark 大家都刷到 95 分以上，它就失去了区分度——"HumanEval 98 分"在今天约等于没说。评测界的军备竞赛就是不断造更难的新考卷。

**二看测的是什么**。MMLU 高说明知识面广，不代表代码强；SWE-bench 高说明工程能力强，不代表写作好。**拿和自己场景最接近的那项看**，别看总分。

## 刷榜与过拟合：跑分高体感差的第一个原因

Benchmark 的考题是公开的。公开就意味着——考题可能混进训练数据。

这叫**数据污染（Contamination）**：模型可能"背过这套卷子"。厂商未必故意作弊，海量抓取的训练数据里混入评测题几乎难以避免，但结果一样：跑分虚高，真实能力没那么强。

更微妙的是**面向榜单优化**：训练时有意往主流 Benchmark 的题型上使劲。模型确实变强了——在那类题上。就像应试教育刷题班,考分高，能力未必同步。

这是"跑分高体感差"的第一个来源：**你日常用的任务，和考卷上的题型不一样。**

---

## Arena / Elo：盲测投票排名

对刷榜的一种制衡是 **LMArena** 这类竞技场评测：

真实用户提一个问题，系统随机安排两个匿名模型回答，用户投票哪个更好——投完才揭晓是谁。海量投票用 **Elo 等级分**（国际象棋那套排名算法）汇总成排行榜。

优点：题目来自真实用户、无法提前背题、反映的是"体感"。

局限也要知道：投票偏好答案的**风格**——更长、格式更漂亮、更自信的回答容易赢，哪怕内容并不更准。于是又出现了"面向 Arena 优化"的现象：把回答调得讨喜。风格分和能力分依然会纠缠。

---

## 跑分高体感差：完整的答案

汇总起来，落差来自四层：

1. **题型错配**：Benchmark 测的不是你的任务
2. **污染与刷榜**：分数本身有水分
3. **饱和**：头部模型在旧考卷上都接近满分，分差没有意义
4. **体感偏差**：你的"体感"也受风格影响，未必比跑分更客观

所以成熟的用法是：**跑分做初筛（选和场景对口的项目看），Arena 看大众体感，最终拿自己的真实任务测**——构造几十个自己场景的样本，候选模型各跑一遍，人工评。这份"私有 Benchmark"没有污染、没有错配，是唯一完全可信的数字。
