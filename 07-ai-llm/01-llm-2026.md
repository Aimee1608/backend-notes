# 现在的 LLM 是什么：会思考、会看图、会干活

如果你对大模型的印象还停留在"一个很会聊天的机器人"，那这个认知大概落后了三年。

2026 年的模型——GPT-5.5、Claude Opus 4.8、Gemini 3 系、DeepSeek-V4 这一批——和当年那个"帮我写篇作文"的 ChatGPT，已经不是同一个物种。要上手大模型应用开发，第一件事是刷新对"它是什么"的认知。

---

## 本质没变：预测下一个词

先说没变的部分，这是理解一切的地基。

LLM 的工作方式从始至终只有一件事：**给定前面的文本，预测下一个最可能出现的词（token），然后把预测结果接上去，继续预测下一个**。像一个超强的自动补全，一个字一个字往外蹦。

这决定了它的几个"天性"：

- **它不是数据库**。它不"查资料"，是根据训练时见过的海量文本，生成"概率上最合理"的内容。所以会有幻觉——生成的内容合理但不真实。
- **它没有实时信息**。训练截止后发生的事，它不知道（除非你喂给它，或让它调搜索工具）。
- **同一个问题每次答案可能不同**。生成过程带有随机采样，这是特性不是 bug。

所有围绕大模型的工程手段——检索、工具调用、输出校验——本质上都是在这个"文本补全引擎"外面搭脚手架。

---

## 变的部分：三个能力维度

三年的迭代，模型在三个维度上长出了新能力。看懂这三个维度，就能看懂现在所有模型发布公告。

### 维度一：会思考（Reasoning）

早期模型是"脱口而出"型：问完立刻答，答错也不回头。

现在的主流模型都内置了**思考模式**（各家叫法不同：thinking、reasoning、Deep Think）。收到复杂问题时，模型会先在内部生成一段"思考过程"——拆解问题、尝试思路、自我纠错——然后才给出最终答案。

这不是营销话术，是训练方式的真实改变：模型被专门训练过"先推理再回答"，在数学、代码、多步规划类任务上，准确率和三年前有代差。

代价也是真实的：思考过程消耗 token（要花钱），也消耗时间（响应更慢）。所以现在的模型大多支持按需开关思考模式——这是使用者要做的日常决策，后面第 02 篇专门讲。

### 维度二：会看图听声（Multimodal）

"多模态"的意思是：输入输出不再局限于文字。

现在的旗舰模型可以直接：

- **看图**：不是 OCR 识字，是理解——扔一张报表截图问"哪个品类增长最快"，它能读懂图表结构再回答
- **读文档**：PDF 里的表格、版式、图片，直接理解，不需要先转成纯文本
- **听音频、看视频**：部分模型支持（Gemini 系在这个维度走得最靠前，能直接吃视频输入）

对应用开发的意义：以前要接一个 OCR 服务 + 一个表格解析服务 + 一个 LLM 才能处理"用户上传的合同截图"，现在一个多模态模型直接搞定。**一批中间处理环节正在消失。**

### 维度三：会干活（Agentic）

这是三年里变化最大、也是当前竞争最激烈的维度。

早期模型只能"给建议"：你问它怎么查数据库，它告诉你 SQL 怎么写，然后你自己去执行。

现在的模型可以"自己动手"：给它配上工具（查数据库、调接口、读写文件、操作浏览器），它会自己决定调哪个工具、看结果、决定下一步，循环往复直到任务完成。这个形态叫 **Agent**。

写代码是目前 Agent 落地最深的场景——模型可以自己读代码库、改代码、跑测试、看报错、再改，一轮轮迭代到测试通过。主流厂商的旗舰模型都在按"能自主工作几小时"来设计和宣传 agentic 能力。

对研发来说，这个维度改变了"接入大模型"的含义：不再只是"加个问答框"，而是"把模型接进工作流，让它执行任务"。

## 2026 年的几个"新常态"

把认知校准到当下，几个事实：

**1M token 上下文是标配了。** 三年前 4K-8K 的窗口是主要瓶颈，现在主流旗舰都到了 100 万 token 量级（大约能塞下几百万字中文）。窗口不再是稀缺资源——但这不代表"什么都往里塞"是对的，成本和精度问题依然存在（第 11 篇细讲）。

**价格降了两个数量级。** 同等能力的调用成本，三年降了百倍量级。很多因为"太贵"被毙掉的方案，现在值得重新评估。

**指令遵循从"哄"变成了"说清楚就行"。** 早期要用各种提示技巧"哄"模型听话，现在的模型对普通描述的理解已经足够好。一批曾经必学的 Prompt 技巧正在失效（第 16 篇专门盘点）。

**模型之间在收敛，也在分化。** 收敛的是基础能力：上下文长度、多模态、工具调用，大家都有。分化的是侧重：有的模型强在代码，有的强在多模态，有的strong在性价比——所以"选哪个模型"变成了按场景决策的问题，没有全能冠军（第 03 篇讲怎么看参数、怎么选）。

## 对研发意味着什么

理解了"会思考、会看图、会干活"这三个维度，你在接需求时的判断框架就有了：

- 需求是**复杂推理**（分析、规划、代码架构）→ 关注模型的思考能力，考虑开启推理模式
- 需求涉及**图片 / 文档 / 音视频** → 直接用多模态能力，别急着上传统的解析服务
- 需求是**执行任务**（查数据、走流程、自动化操作）→ 这是 Agent 场景，重点在工具设计和流程控制

而无论哪种场景，都别忘了地基：它本质上是一个概率驱动的文本补全引擎。它很强，但它会编、会错、会不稳定——工程上的一切设计，都是围绕"怎么用好一个不完全可靠但极其强大的组件"展开的。

这个系列接下来要讲的，就是这套工程方法。
