# 产品黑话词扫盲：发布会上的词，背后各是什么技术

厂商发布会有自己的语言体系：Deep Research、Computer Use、Artifacts、Copilot、Guardrails……这些词一半是技术、一半是包装。

这篇的任务：剥掉营销壳，指出每个词对应的技术实体。以后再看发布会，能自动完成"翻译"。

---

## Thinking / Reasoning / Deep Think

**对应技术：推理模式**（前面第 02 篇讲过的那个）。

各家给同一类能力起了不同名字：Extended Thinking、Reasoning、Deep Think……剥开叫法，都是"回答前先生成内部推理过程，用推理时的额外计算换答案质量"。

看到这类词，关心三件事就够：能不能手动开关、思考预算怎么控制、思考 token 怎么计费。

---

## Deep Research

**对应技术：一个预制的多步搜索 Agent。**

产品形态：你提一个研究问题，它花几分钟到几十分钟，自主搜索几十上百个网页、交叉比对、最后产出一篇带引用的研究报告。

拆开看，里面没有新的模型能力，是几个已有能力的组合：推理模式（规划研究路径）+ 搜索工具调用（反复检索）+ 长上下文（装下所有搜到的材料）+ 长时任务运行。它的价值在于厂商把这个 Agent 流程打磨好了直接给你用。

对研发的启示：这类产品就是 Agent 工程的样板间——看它的行为方式（先规划、再多轮搜索、边搜边调整关键词），就是在看一个成熟 Agent 的设计。

---

## Computer Use / Operator 类

**对应技术：模型操作图形界面的能力。**

模型看屏幕截图 → 决定下一步操作（点击坐标、输入文字、滚动）→ 执行 → 看新截图 → 继续。循环往复，像人一样用电脑。

它解决的是"没有 API 的系统怎么自动化"——老旧的内部系统、只有网页界面的第三方服务，模型直接当人肉点击器的替代品。

现状要客观：**这是最不成熟的主流能力**。速度慢（每步都要截图-推理-操作）、成本高、可靠性有限，界面稍有变化就可能迷路。适合演示和低频流程，大规模生产落地还在路上。有 API 可调时，永远优先调 API。

---

## Artifacts / Canvas

**对应技术：对话产物的独立渲染区 + 增量编辑。**

传统对话里，模型生成的代码/文档混在聊天流里，改一处就重新生成一遍全文。Artifacts/Canvas 类功能把"产物"（代码、文档、网页）放进一个独立面板，模型可以对它做局部修改，用户也能直接编辑。

本质是**产品交互创新，不是模型能力**——底层还是同一个模型，变的是产物的管理方式。但它值得注意的原因是：这代表了"对话式 AI"向"工作台式 AI"的形态迁移，你做 AI 产品设计时大概率要面对同样的选择。

---

## Copilot vs Agent

这两个词的区别是**控制权在谁手里**：

- **Copilot（副驾驶）**：人主导，AI 辅助。代码补全、写作建议——AI 提议，人决定采纳与否。每一步都有人把关。
- **Agent（代理）**：AI 主导执行，人给目标和边界。"把这个 bug 修了"，然后它自己读代码、改、测试，最后人验收结果。

同一个模型可以支撑两种形态，区别在产品设计：**人审核每一步，还是只审核结果**。风险特征完全不同——Copilot 的错误在采纳前就会被人看到，Agent 的错误可能已经执行完了才被发现。这决定了 Agent 需要一套 Copilot 不需要的工程：权限控制、操作审计、回滚机制。

宣传语里"从 Copilot 到 Agent"说的就是这个交接：AI 从"给建议的"变成"干活的"。

## Grounding

**对应技术：让模型的回答锚定在给定的事实来源上。**

裸奔的模型靠训练记忆回答，会编。Grounding（接地）指把模型的输出约束到可靠来源：回答前先检索（搜索引擎、知识库），要求答案基于检索结果并给出引用。

看到"grounded in search results"、"带引用回答"这类说法，指的就是这个。它是对抗幻觉的主要手段——注意是"主要手段"不是"根治"：模型依然可能曲解引用的内容，引用了不代表引用对了。

---

## Guardrails

**对应技术：模型输入输出两端的安全过滤层。**

Guardrails（护栏）是包在模型外面的检查机制：

- **输入端**：拦截恶意提示、注入攻击、违规请求
- **输出端**：检查生成内容——有没有违规内容、有没有泄露敏感信息、格式是否合规

实现方式从简单的关键词规则，到专门的小型审核模型，到"用另一个 LLM 检查这个 LLM"。企业产品宣传里的"企业级安全护栏"，指的就是这一层的完善程度。

对研发的意义：这层是**你自己要建的**——模型 API 自带的安全机制针对通用风险，你的业务规则（不能承诺退款、不能提竞品、不能泄露内部信息）只能自己加护栏。

## 翻译练习

发布会原文风格："全新的 XX 助手，基于深度推理引擎，支持 Deep Research 与 Computer Use，通过 Grounding 确保回答可信，企业级 Guardrails 保驾护航，实现从 Copilot 到 Agent 的跨越。"

翻译：一个带思考模式的模型，预制了多步搜索 Agent 和界面操作能力，回答带检索引用，输入输出有安全过滤，产品形态从"人审每步"转向"自主执行"。

——没有一个词是魔法，全部有对应的技术实体。这就是扫盲的意义：听得懂，才能判断哪些对你的场景有用。
