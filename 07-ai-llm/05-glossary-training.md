# 训练流程词扫盲：一个模型是怎么"炼"出来的

预训练、后训练、SFT、RLHF、DPO、对齐、微调、LoRA——这串词经常一起出现，关系却没人讲清楚。

其实它们描述的是同一条流水线的不同工序。沿着"一个模型从无到有"的顺序走一遍，所有词就都各归其位了。

---

## 第一道工序：预训练（Pretraining）

从随机初始化的参数开始，把海量文本（网页、书籍、代码，万亿 token 量级）喂给模型，让它做一件事：**看前文，猜下一个词**。猜错了就调整参数，重复几万亿次。

这个阶段耗掉整个训练过程 90% 以上的算力，成本以千万到亿美元计。产出物就是上一篇说的 **Base 模型**——一个"读过全世界的文本、只会续写"的原始大脑。

它博学但不好用：你问问题，它可能续写出更多问题；你让它干活，它可能开始点评你的措辞。它没有"我在和人对话"的概念。

---

## 第二道工序：后训练（Post-training）

把 Base 模型调教成有用助手的全部工序，统称后训练。这三年模型能力的突飞猛进，很大程度上是后训练技术的进步——预训练决定了模型的知识上限，后训练决定了这些知识能不能被好好用出来。

后训练里最主要的两步：

### SFT：监督微调（Supervised Fine-Tuning）

拿几万到几百万条高质量的"问题-理想回答"对，让模型模仿。这一步教会模型**对话的格式和规矩**：用户提问就回答、说"写代码"就输出代码、遇到危险请求要拒绝。

SFT 之后，Base 模型就变成了能正常对话的模型。但"能对话"和"答得好"之间还有距离——SFT 只教了模仿，没教判断好坏。

### RLHF / DPO：人类偏好对齐

让模型对同一个问题生成多个回答，人类标注员标出哪个更好，然后用这些偏好数据训练模型"多产出人类喜欢的，少产出人类不喜欢的"。

- **RLHF**（Reinforcement Learning from Human Feedback）：早期主流做法，先用偏好数据训练一个"评分模型"，再用强化学习让模型向高分方向优化。流程复杂但有效——ChatGPT 当年惊艳世界，RLHF 是关键功臣。
- **DPO**（Direct Preference Optimization）：后来的简化方案，跳过评分模型，直接用偏好数据优化。效果相当、流程简单，被广泛采用。

看到这两个词，记住一点就够：**都是在教模型"什么样的回答更好"**，是技术路线之别，不是目标之别。

另外，现在的**推理模型**（会思考的那类）在后训练里还多了一道工序：用强化学习专门训练"推理过程"——让模型在数学、代码这类有标准答案的任务上反复试错，自己学会打草稿。这是近两年后训练最热的方向。

---

## 贯穿全程的词：对齐（Alignment）

对齐不是某道具体工序，是一个目标：**让模型的行为符合人类的意图和价值观**——有用、诚实、无害。上面的 SFT、RLHF/DPO 都是实现对齐的手段。

发布公告里"经过深度对齐"、讨论里"对齐税"（对齐导致模型变保守、能力略降的代价），说的都是这个维度的事。

---

## 用户侧的词：微调（Fine-tuning）与 LoRA

以上都是厂商在出厂前做的事。**微调**是模型出厂后，使用方拿自己的数据继续训练，让模型适配自己的场景——学会公司的术语体系、固定的输出格式、特定领域的行文风格。

**LoRA**（Low-Rank Adaptation）是最流行的微调方法。全量微调要更新所有参数，70B 模型微调一次的显存和算力开销极大。LoRA 的思路：冻结原模型的全部参数，只在旁边加一组很小的"补丁参数"（通常不到原模型的 1%），只训练补丁。

效果：训练成本降一到两个数量级，产出物只是一个几十上百 MB 的补丁文件，可以随时挂载、卸载、切换——同一个基座模型配不同的 LoRA 补丁，就能服务不同场景。

要泼的冷水：**2026 年的多数应用场景，轮不到微调出场**。模型本身够强，加上检索（RAG）和上下文工程，绝大部分需求就解决了。微调适合的是"模型反复不听 Prompt 管教"的顽固行为问题——什么时候真的需要微调，后面章节专门讲。

## 一张图收尾

```
海量文本 ──预训练──→ Base 模型（博学，只会续写）
                        │
                   ┌─ 后训练 ─┐
                   │  SFT      │ 教对话格式
                   │  RLHF/DPO │ 教什么是好回答     ← 对齐目标贯穿其中
                   │  推理RL    │ 教打草稿（推理模型）
                   └───────────┘
                        ↓
                  Instruct 模型（出厂状态，你调 API 用的就是它）
                        │
                （可选）用户微调 / LoRA ──→ 场景定制版
```

下次看到"我们基于 XX-Base 做了 SFT 和 DPO 对齐"，你就知道：他们拿了个原始大脑，教会了它对话，又教了它好坏——一条标准流水线而已。
