# 上下文这么长了，还要 RAG 吗

三年前做知识问答，RAG（检索增强生成）是唯一选项：模型窗口装不下你的文档，只能先检索、再把相关片段塞进去。

现在窗口到了百万 token，一个自然的问题：**还要检索吗？直接把文档全塞进去不行吗？** 答案是"看情况"，而且这个"情况"和三年前完全不同——RAG 没死，但它存在的理由全换了。这篇把新的理由讲清楚，最后给一棵决策树。

---

## 直塞的真实代价

先算清楚"全塞进去"要付什么。第 11 篇讲过四个问题，放到知识库场景里具体化：

**每次请求都为全量文档付费**。一份 300K token 的手册，用户问一个问题，这次请求为 300K 输入付费；问十个问题，付十次。缓存能打折，但缓存有生存时间，间隔一长就要重新写入，写入还可能有溢价。检索方案每次只塞相关的几千 token，输入成本差两个数量级。

**延迟随输入长度涨**。几十万 token 的输入，首字延迟可能十几秒。对话场景里每一句话都让用户等十几秒，不可接受。

**注意力稀释**。文档里 95% 的内容和当前问题无关，模型要在噪声里找信号。"大海捞针"测试高分说明它能找到一句孤立的信息，不说明它在满屏无关内容里的综合判断不受影响。

**内容之间互相干扰**。多份文档塞在一起，模型可能把 A 文档的规则套到 B 文档的问题上。文档越多、越相似（不同版本的同一份合同），这个问题越严重。

所以"能塞"和"该塞"是两回事。窗口解决的是硬约束，没解决经济性和质量。

---

## RAG 仍然成立的四个理由

三年前 RAG 的理由是"塞不下"。现在这个理由基本消失了，换成了四个新的：

### 一、语料规模超过窗口

企业知识库动辄几千份文档、上亿 token。百万窗口在这个规模面前依然是零头。只要语料比窗口大，就必须先筛再塞——这是 RAG 最朴素的理由，只是门槛从"几千 token"抬到了"百万 token"。

### 二、数据实时变化

库存、价格、工单状态、今天的新闻——这些数据分钟级变化。直塞意味着每次请求前重新组装全量数据，缓存全部失效。检索方案只在请求时查最新的那几条，天然适合动态数据。

### 三、权限隔离

不同用户能看的内容不同：销售看不到财务文档，A 部门看不到 B 部门的。直塞没法做权限——塞进去了模型就能看到，靠 prompt 说"不要告诉用户 X 部分"是不可靠的（第 30 篇讲为什么）。检索层做权限过滤，只把用户有权看的内容送进模型，这是**唯一可靠的隔离方式**。

### 四、成本

上面算过的账。高频问答场景（客服、内部知识助手），每天几万次请求，直塞和检索的账单差距是十倍到百倍级。

四个理由里，**权限**是最硬的——它不是"更好"，是"没有别的办法"。其余三个是经济性和质量的权衡。

## 直塞更好的场景

反过来，有些场景检索反而是画蛇添足：

- **一次性任务**：审一份合同、读一份 PR、分析一份报告。文档就一份，问题需要通览全文，切片检索只会丢上下文。直塞。
- **内容强关联**：长报告的前后逻辑、代码库里跨文件的调用关系。切开就断了，检索出来的片段拼不回原来的意思。直塞。
- **小语料 + 低频**：总共几万 token 的 FAQ，一天几十次问答。搭检索管道的工程成本远大于省下的 token 费。直塞，或者干脆全放 system 里吃缓存。
- **需要全局判断**："这份文档里有没有前后矛盾的地方"——检索只能找局部，回答这类问题必须看全貌。直塞。

规律是：**问题需要的信息占文档的比例越高、文档总量越小、问的次数越少，越该直塞**。

## 决策树

拿到一个"给模型接知识"的需求，按顺序问：

1. **有权限隔离需求吗？** 有 → RAG，没有别的选择
2. **语料总量超过窗口（留出足够余量）吗？** 超过 → RAG
3. **数据分钟级变化吗？** 是 → RAG（或者实时查询接口，本质一样）
4. **单次问题需要通览全文吗？** 是 → 直塞
5. **高频调用吗？** 一天上千次以上 → 算一下账，多半是 RAG；低频 → 直塞

走到第 5 步还没定的，选直塞——工程简单、效果通常更好，等账单或延迟出问题再改。**RAG 是工程决策，不是默认选项**，这是它和三年前最大的区别。

## 2026 年的混合形态

实际生产里越来越多的做法是两者混用：

- 用检索从大语料里筛出**相关的几份文档**，然后把这几份**完整**塞进上下文，而不是只塞几个片段。检索负责"找到哪几份"，长上下文负责"完整理解它们"。这解决了老 RAG 最大的痛点——片段切碎了上下文。
- 一个应用里按接口分：客服问答走检索（高频、权限），合同分析走直塞（一次性、通览）。
- 让模型自己决定要不要检索、检索什么——这是下一步的形态，第 19 篇讲。

RAG 从"必需品"变成了"工具箱里的一件工具"。什么时候拿它出来，是这一章剩下三篇要回答的问题。
