# 缓存 demo:三大坑与防护(零依赖)

配套文章:《缓存:为什么快、三大坑、和数据库怎么保持一致》

这个 demo **不用装 Redis** —— 用内存模拟"慢数据库 + 带 TTL 的缓存",
聚焦把缓存的几个经典问题和防护**用「回源次数」直观看出来**。

## 怎么跑

```bash
node demo.js
# 或
npm start
```

## 演示了什么

| 场景 | 问题 | 防护 | 看什么 |
|---|---|---|---|
| 零 | 缓存的一生:创建 / 命中 / 删除 | Cache-Aside 读写 | `[cache] SET / HIT / DEL / MISS` 日志 |
| 一 | 缓存的价值 | Cache-Aside | 回源次数 10 → 1 |
| 二 | 缓存穿透(狂查不存在的 key) | 缓存空值 | 回源次数 10 → 1 |
| 三 | 缓存击穿(热点 key 过期瞬间并发) | 单飞 / 互斥 | 回源次数 100 → 1 |
| 四 | 缓存雪崩(大批 key 同时过期) | TTL 加随机抖动 | 过期时刻跨度 ~0 → 摊开 |
| 五 | 缓存一致性(更新后) | 更 DB + 删缓存 | 再读拿到新值 |

## 文件

- `cache-lib.js` —— 内存缓存 + 模拟慢 DB + Cache-Aside 读写 + 各防护开关(带中文注释)
- `demo.js` —— 跑上面 5 个场景,打印对比

## 注意

真实项目里缓存用 **Redis**,这里用内存 `Map` 模拟,是为了**零依赖、聚焦逻辑**。
换成 Redis 时思路一一对应:`cache.get/set/del` → Redis 的 `GET / SETEX / DEL`,
单飞锁 → Redis 分布式锁(`SET key val NX EX`),其余完全一致。
