# API 设计 demo:好接口长什么样(零依赖)

配套文章:《API 设计:好接口长什么样 —— 能跑通 ≠ 好接口》

这个 demo **不起真实 server** —— 用纯函数 + 内存模拟"接口处理",
聚焦把"能跑通"和"好接口"的差距,用三个对照场景**直观看出来**。

## 怎么跑

```bash
node demo.js
# 或
npm start
```

跑完即退出,无需任何依赖。

## 演示了什么

| 场景 | 烂做法 | 好做法 | 看什么 |
|---|---|---|---|
| 一 · 幂等 | 来一次建一单 | Idempotency-Key + 服务端去重 | 最终订单数 2 → 1 |
| 二 · 分页 | offset 深分页 | 游标分页 | 扫描行数 10000 → 10 |
| 三 · 错误处理 | 全返 200 + "系统异常" | 状态码 + `{code,message,details}` | 调用方能不能定位问题 |

## 文件

- `lib.js` —— 三个场景的"接口处理"模拟:幂等创建、offset/游标分页、烂/好两种错误返回(带中文注释)
- `demo.js` —— 跑上面 3 个场景,打印对比

## 注意

这里用内存 `Map` / 数组模拟,是为了**零依赖、聚焦逻辑**。换成真实后端时思路一一对应:

- 幂等去重表 → Redis / 数据库唯一索引(`Idempotency-Key` 落库);
- 游标分页 → SQL 的 `WHERE id > ? ORDER BY id LIMIT ?`(配合索引);
- 统一错误结构 → 框架的全局异常处理器,把异常统一映射成 `{code,message}` + 正确状态码。
