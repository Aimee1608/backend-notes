# 服务月成本估算器 demo(零依赖)

配套文章:《服务成本账:一个服务一个月烧多少钱》

把一个服务的成本拆成 **计算 / 数据库 / 缓存 / 公网流量 / 对象存储 / 日志** 六项,
各项相加,算出一个月大概烧多少钱,并打印**每项占比** —— 直观看到"钱花在哪"。

> ⚠️ demo 里所有单价都是**示例值**,只为演示"怎么算这笔账"。
> 真实价格随云厂商 / 地域 / 规格 / 折扣浮动很大,**务必以云厂商官网价目表为准**。

## 怎么跑

```bash
node demo.js
# 或
npm start
```

零依赖,`node demo.js` 直接跑,跑完即退出。

## 演示了什么

跑两个示例场景,各打印一张成本明细表(已按金额从大到小排序):

| 场景 | 设定 | 想让你看到的 |
|---|---|---|
| 小服务 | 低流量内部 API,峰值 100 QPS | 大头在"固定包月"的数据库 / 计算上 |
| 中等服务 | 对外 API,峰值 1000 QPS | 大头转移到**公网流量**(占比最高)|

核心结论一眼可见:**流量大了之后,公网出口往往是最贵的一块** —— 这正是"大文件要走 CDN"的原因。

## 算账思路

- **实例数** = `ceil(峰值 QPS / 单台可承载 QPS)` —— 必须向上取整,且要扛住峰值。
- **计算费** = 实例数 × 实例月单价。
- **数据库 / 缓存** = 云上托管实例的月单价(包月)。
- **流量费** = 月流量 GB × 单价/GB(公网出口,最容易被忽视)。
- **对象存储** = 用量 GB × 单价/GB·月。
- **日志** = 日志 GB × 综合单价(存储 + 检索)。
- 总额 = 以上相加;再给每项算出占比。

## 文件

- `lib.js` —— 估算函数 `estimateMonthlyCost`,各项计算逻辑 + 单价示例(带中文注释)。
- `demo.js` —— 跑两个示例场景,打印明细表 + 总额 + 占比条。

## 自己试试

改 `demo.js` 里任一个用量 / 单价再跑,看总额和占比怎么变:
- 把 `trafficGb`(月流量)调大 → 体会公网流量为什么得走 CDN;
- 把 `qpsPerInstance`(单台承载)调高 → 实例数下降,计算费随之降(合理压测/选型的价值)。
